# 远程客户端部署

## 架构

- RTX 3080 电脑：运行 FastAPI、PaddleOCR、识别队列、MySQL、金蝶同步和图片归档。
- 普通电脑：连接两台海康相机，只负责抓拍、本地缓存、上传和显示结果。
- 开发阶段可在 RTX 3080 电脑上同时运行服务端和客户端，不需要立即准备第二台电脑。

生产部署时，服务器不连接、不打开相机。浏览器中的实时画面来自笔记本本机的
`127.0.0.1:8812`；抓拍的原始 JPEG 由笔记本上传到服务器，服务器验证后原样保存并识别。

## 服务端

在 `.env` 中设置：

```env
CLIENT_API_KEY=请设置一个足够长的随机密钥
CAM_SUPERVISOR=0
OCR_DEVICE=gpu
```

启动局域网服务：

```powershell
.venv\Scripts\python.exe -m uvicorn app.server:app --host 0.0.0.0 --port 8000
```

服务端只运行一个 GPU Worker，客户端可并发上传，识别任务按先后顺序执行。任务文件保存在 `uploads/remote_jobs/<job_id>/`，服务重启后未完成任务自动重新排队。

## 客户端

普通电脑需要安装：

- Python 3.12 和项目客户端依赖。
- 海康 MVS SDK。
- 两台相机的序列号、曝光、增益和方向配置。

复制 `client/client_config.example.json` 为 `client/client_config.json`，配置服务端地址、相同的 API Key、工位编号和缓存目录。

测试连接：

```powershell
.venv\Scripts\python.exe client\qc_client.py health
```

启动客户机采集代理（保持窗口运行）：

```powershell
client\run_capture_agent.bat
```

质检员在客户机浏览器打开 `http://服务器IP:8000/camera`。实时预览来自客户机本机
`127.0.0.1:8812`，点击“拍照并检测”后，由客户机抓取正反面照片并上传服务器识别。

命令行方式仍可用于诊断：

```powershell
.venv\Scripts\python.exe client\qc_client.py capture --batch-id 123 --operator 质检员A --wait
```

使用已有图片进行同机开发测试：

```powershell
.venv\Scripts\python.exe client\qc_client.py upload-files --front uploads\0083\front.jpg --back uploads\0083\back.jpg --batch-id 123
```

网络中断时，照片保留在缓存目录的 `pending` 中。网络恢复后执行：

```powershell
.venv\Scripts\python.exe client\qc_client.py sync
```

服务端确认接收后，任务移动到 `confirmed`，不会因网络失败丢失照片。相同 `job_id` 重复上传不会重复识别或重复入库。

## 联调顺序

1. 同机使用已有正反面照片验证上传、排队和结果查询。
2. 同机连接真实相机验证抓拍、缓存和上传。
3. 使用普通电脑访问 RTX 3080 服务端的局域网 IP。
4. 拔网线验证待上传缓存和恢复补传。
5. 两台客户端同时上传，验证排队顺序和显存占用。

## 3080 本机同时作为客户机

相机也接在 3080 电脑上时，直接运行项目根目录的 `run.bat`。它会同时启动：

- `0.0.0.0:8000`：服务器、GPU 识别和业务页面。
- `127.0.0.1:8812`：本机相机采集代理和实时预览。

关闭全部本机服务：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\stop_local_all.ps1
```
